📋 code-audit-paper

🔍 Audit Flow

Phase 1 downloads everything · Phase 2 audits and generates reports

📦 Phase 1 · Preparation

Download the paper and code.
Determine a clean directory name after reading the LaTeX source.

1 🔧 Environment Check
Check available commands: python or python3? git? curl? Record the right answers for this system.
2 📄 Download from arXiv
Accept arXiv ID, paper title, or URL. Fetch PDF + LaTeX source via arXiv API. Don't name the directory yet — use a temp name for now.
✅ LaTeX → continue ❌ None → note in report
3 ✏️ Name the Directory
Now read the LaTeX source. Look for the method acronym (e.g. ResNet, ViT, LoRA). If none found, use the first 6 words of the title. Rename to <MMDD>/<HHMM>-<name> — timestamp prefix keeps multiple audits sorted chronologically.
💡 Example: 0722/1914-visual-autoregressive-modeling
4 🔗 Find & Clone Code
Scan LaTeX for GitHub links. Identify the real code repo (skip datasets, dependencies). Clone and verify it contains actual implementation code.
✅ Has code → continue ❌ None → note in report
🔬 Phase 2 · Audit

Run the automated scan, do the four-dimension audit, generate QA pages, and save the handoff prompt.

5 🧪 Automated Scan
Parse LaTeX claims, analyze code structure, cross-reference. Outputs audit/audit_report.html — a scaffold with paper overview, code stats, and placeholder areas.
6 🔬 Four-Dimension Audit
Read LaTeX and code. Check all four dimensions and write findings into audit_report.html.
🔁 Reproducibility Datasets, weights, baselines
🧩 Method Consistency Paper claims vs. code
🔬 Experiment Details Hyperparams, preprocessing
📊 Code Coverage Which experiments have code?
7 💬 Generate QA Pages
Translate the Introduction into a three-column HTML page (EN · plain language · ZH). Each paragraph is a card. More pages for follow-up questions.
qa/introduction.html · qa/method.html · …
✓ 📋 Save Handoff Prompt
Write a detailed handoff prompt to handoff_prompt.md. Includes the first-pass audit summary, all file paths, and 4 deep re-audit tasks.
✅ Audit complete! Open audit/audit_report.html in any browser.
Optional
🔍 If you want a deeper second opinion
📋 Read handoff_prompt.md
Open the prompt file saved by Phase 2. Copy its content and paste into a new session. You can choose any model — a smarter one is recommended but not required.
🔍 Deep Re-Audit (4 Tasks)
Go deeper than the first-pass audit:
  1. 1. Method deep-dive — re-examine every ⚠️, find missed details, spot hidden components
  2. 2. Experiment verification — check every hyperparameter, every preprocessing step
  3. 3. Full coverage sweep — list every experiment (incl. appendix), find code for each
  4. 4. Claim-by-claim review — judge which claims are verifiable vs. vague
✓ Output Detailed Report
Create audit/audit_report_deep.html — a new, more detailed report. Does not modify the first-pass report. Includes code snippets with line numbers.

🔍 审计流程

阶段一下载所有材料 · 阶段二审计并生成报告

📦 阶段一 · 准备

下载论文和代码。
目录名在读完 LaTeX 源码后再定——而不是提前猜。

1 🔧 环境检查
检查命令：python 还是 python3？有没有 git？curl？记下正确的名字。
2 📄 从 arXiv 下载
接收 arXiv ID、论文标题或链接。通过 arXiv API 抓取 PDF + LaTeX 源码。先不要定目录名——暂时用临时名。
✅ 有 LaTeX → 继续 ❌ 没有 → 报告中注明
3 ✏️ 确定目录名
现在读 LaTeX 源码，找论文提出的方法缩写（如 ResNet、ViT、LoRA）。找不到就用标题前 6 个单词。重命名为 <月日>/<时分>-<名字>——时间戳前缀让多次审计自动按时间排序。
💡 例如：0722/1914-visual-autoregressive-modeling
4 🔗 查找并克隆代码
扫 LaTeX 找 GitHub 链接，判断哪个是真正的代码仓库（跳过数据集、依赖库）。克隆后确认有实际代码。
✅ 有代码 → 继续 ❌ 没有 → 报告中注明
🔬 阶段二 · 审计

跑自动扫描，做四维度审计，生成 QA 页面，保存交接提示词。

5 🧪 自动扫描
解析 LaTeX 声明、分析代码结构、交叉比对。输出 audit/audit_report.html——含论文概览、代码统计和占位区域。
6 🔬 四维度审计
读 LaTeX 和代码，检查四个维度，把发现写入 audit_report.html。
🔁 可复现性 数据集、权重、baseline
🧩 方法一致性 论文声明 vs. 代码
🔬 实验细节 超参数、预处理
📊 代码覆盖率 哪些实验有代码？
7 💬 生成 QA 页面
把引言翻译成三栏 HTML（英 · 人话 · 中）。每个自然段一张卡片。后续问题继续在 qa/ 下新建。
qa/introduction.html · qa/method.html · …
✓ 📋 保存交接提示词
把详细交接提示词写入 handoff_prompt.md。含首轮审计摘要、所有文件路径、深度重审 4 项任务。
✅ 审计完成！audit/audit_report.html 浏览器直接打开看。
可选
🔍 如果你想要更深入的第二意见
📋 读取 handoff_prompt.md
打开阶段二保存的提示词文件。复制内容，粘贴到新会话窗口。你可以选任何模型——聪明模型推荐但不强制。
🔍 深度重审（4 项任务）
比首轮审计挖得更深：
  1. 1. 方法深挖 — 重审每个 ⚠️，找遗漏细节，发现隐藏组件
  2. 2. 实验逐项核实 — 检查每个超参数、每个预处理步骤
  3. 3. 全覆盖扫描 — 列出每个实验（含附录），逐个找代码
  4. 4. 逐条声明验证 — 判断每条声明是可验证的还是模糊的
✓ 输出详细版报告
新建 audit/audit_report_deep.html——一份更详细的独立报告，不修改首轮报告。含具体代码片段引用和行号。
