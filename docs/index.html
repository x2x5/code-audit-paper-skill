🔍 Audit Flow

Two-phase design — cheap model for prep work, smart model for deep analysis

⚡ Phase 1 · Preparation

Run this phase with a cheap model (e.g. DeepSeek Flash). Download everything, run the automated script, then stop and output a handoff prompt. No deep analysis — that's Phase 2's job.

1 🔧 Environment Check
Before anything else, check which commands are available: Is it python or python3? pip or pip3? Is git installed? curl or wget?
💡 Different systems name these differently. Running the wrong command causes pointless errors. Check once, use the right name everywhere. If git or Python is missing → abort with a clear message.
2 📥 Parse the Input
You give the tool a paper reference — an arXiv ID (like 2301.12345), a full paper title, or a complete arXiv URL. The tool figures out which paper you mean and creates a clean folder name (the method acronym like "ResNet" or the first six words of the title).
3 📄 Download from arXiv
Fetches two things via the arXiv API:
① The PDF — the typeset paper. Almost always available.
② The LaTeX source bundle — the raw .tex files. This is crucial: without it we can't scan for GitHub links or parse claims.
✅ LaTeX found
📄 Source saved
Extracted to latex/. All .tex and .bib files ready.
❌ No LaTeX
⛔ Skip to handoff
arXiv has no .tex source. Note this in the handoff prompt — Phase 2 can only do a limited PDF-only review.
4 🔗 Find & Clone Code
Reads every LaTeX file to find GitHub links inside \url{}, \href{}{}, and nearby text. Identifies which link points to the actual code repository (skips datasets, dependencies, personal pages).
🔎 If no link is found in the LaTeX, falls back to searching GitHub by paper title. Once identified, clones the repo into code/ and verifies it contains actual code (not just a README).
✅ Repo found & has code
📦 Code ready
Cloned to code/. Real implementation files present.
❌ No repo / empty
⛔ Skip to handoff
Note in the handoff prompt: code is unavailable. Phase 2 can only review the paper text.
5 🧪 Run Automated Audit
The audit script parses LaTeX claims, analyzes code structure, and cross-references them — all automatically. Outputs a single HTML page: audit/audit_report.html (open it in any browser).
📊 This generates the scaffold for Phase 2: paper overview, code stats, method/dataset matching, extracted claims, key files, and a summary section with placeholder areas for the deep audit.
6 📋 Output Handoff Prompt
Phase 1 ends here. Do NOT do any deep analysis. Instead, output a self-contained handoff prompt that includes:
• Paper title, arXiv ID, and all directory paths
• Summary of what was downloaded (LaTeX, code, audit report)
• Key stats from the automated scan
• A complete 7-step task list for Phase 2
• Instructions for where to write findings in audit_report.html
📋 The user copies this prompt, opens a new session, switches to a smart model (e.g. DeepSeek Pro), pastes it, and Phase 2 begins — with no context lost.

🧠 Phase 2 · Deep Analysis

Run this phase with a smart model (e.g. DeepSeek Pro). Read the paper, read the code, compare every claim, and write findings into audit/audit_report.html. Then generate QA pages.

7 📖 Read All Materials
Open audit/audit_report.html to see the automated scan results. Read the LaTeX source (focus: abstract, introduction, method, experiments). Browse the code repository structure and key implementation files.
🎯 Everything is already downloaded. You're starting with a full picture of what the paper claims and what the code contains.
8 🔬 Four-Dimension Deep Audit
Go through each dimension and write findings directly into audit/audit_report.html (the HTML has placeholder sections ready for you to fill in):
▼ Four Audit Dimensions ▼
🔁
Reproducibility
Are datasets available with download scripts? Are pretrained weights provided? Are baseline methods actually implemented, or just numbers copied from other papers?
🧩
Method Consistency
Line-by-line: what the paper says vs. what the code does. Catch exaggerations — "novel attention mechanism" that's just standard multi-head attention.
🔬
Experiment Details
Hyperparameters, data preprocessing, evaluation metrics — does the paper's description match the config files and training scripts?
📊
Code Coverage
For every experiment, table, and figure in the paper: is there corresponding code? Flags results that can't be reproduced.
9 💬 Generate QA Pages
Default: translate the Introduction into a three-column HTML page (qa/introduction.html) — English original · plain-language explanation · Chinese translation.
📝 Each paragraph becomes a card. Readers can browse the paper like an annotated bilingual guide. Follow-up questions get their own pages in qa/ — same card-based style, one HTML file per question.
qa/introduction.html  ·  qa/method.html  ·  qa/experiments.html  ·  …
✓ Audit Complete
The user now has a complete audit/audit_report.html with all four dimensions filled in, plus QA pages for the introduction and any follow-up questions. Everything is in self-contained HTML files — open in any browser, no server needed.

🔍 审计流程

两阶段设计 — 便宜模型做体力活，聪明模型做深度分析

⚡ 阶段一 · 准备

用便宜模型（如 DeepSeek Flash）跑这个阶段。 把需要的文件全部下载好，自动脚本跑完，然后停下来，输出交接提示词。 不要做任何深度分析——那是阶段二的事。

1 🔧 环境检查
任何操作之前，先检查环境里装了哪些工具：Python 命令是 python 还是 python3？pip 是 pip 还是 pip3？有没有 git？ 下载工具是 curl 还是 wget？
💡 不同系统命令名不一样，不检查就直接跑会导致无谓的报错。 检查一次，后面全部用正确的名字。 如果 git 或 Python 不可用 → 直接中止，告诉用户原因。
2 📥 解析输入
你给工具一个论文引用——可以是 arXiv ID（如 2301.12345）、 论文完整标题，或者 arXiv 完整链接。 工具会自动识别你要审的是哪篇论文，并给它起一个干净易读的文件夹名 （用方法缩写如 "ResNet"，或者标题前六个词）。
3 📄 从 arXiv 下载
通过 arXiv API 获取两种文件：
① PDF 文件——排版好的论文，几乎总能下载到。
② LaTeX 源码包——原始 .tex 文件。 这是关键：没有它就无法扫描 GitHub 链接，无法解析论文声明。
✅ 有 LaTeX
📄 源码已保存
解压到 latex/，所有 .tex 和 .bib 就绪。
❌ 没有 LaTeX
⛔ 跳到交接提示词
arXiv 没有 .tex 源文件。在交接提示词中注明——阶段二只能做有限的 PDF 审阅。
4 🔗 查找并克隆代码
逐篇阅读所有 LaTeX 文件，从中找出 GitHub 链接—— 检查 \url{}、\href{}{} 和链接周围的文字， 判断哪个指向论文真正的代码仓库（跳过数据集、依赖库、个人主页）。
🔎 LaTeX 里找不到链接时，自动到 GitHub 上按论文标题搜索。 确定目标仓库后克隆到 code/， 并确认里面确实有代码（不只是 README）。
✅ 找到且有代码
📦 代码就绪
已克隆到 code/，有实际实现文件。
❌ 没找到 / 空仓库
⛔ 跳到交接提示词
在交接提示词中注明代码不可用。阶段二只能审阅论文文本。
5 🧪 运行自动审计脚本
审计脚本解析 LaTeX 声明，分析代码结构，交叉比对——全部自动完成。 输出单个 HTML 网页：audit/audit_report.html （浏览器直接打开即可查看）。
📊 这为阶段二生成了脚手架：论文概览、代码统计、方法/数据集匹配、 提取的声明、关键文件，以及带有虚线占位区域的总结部分（等待阶段二填入深度审计结果）。
6 📋 输出交接提示词
阶段一到这里就结束了。不要做任何深度分析。 输出一段自包含的交接提示词，内容包括：
• 论文标题、arXiv ID、所有目录路径
• 已下载内容摘要（LaTeX、代码、审计报告）
• 自动扫描的关键统计数据
• 阶段二的完整 7 步任务清单
• 结果写入 audit_report.html 的具体位置说明
📋 用户复制这段提示词，打开新会话窗口， 切换到聪明模型（如 DeepSeek Pro），粘贴进去， 阶段二就自动接上了——不会丢失任何上下文。
📋 复制提示词 · 切换模型 · 粘贴到新窗口 📋

⬆️ 阶段一结束  ·  用户从便宜模型切换到聪明模型  ·  阶段二开始 ⬇️

🧠 阶段二 · 深度分析

用聪明模型（如 DeepSeek Pro）跑这个阶段。 读论文、读代码、逐条对比声明，把发现写入 audit/audit_report.html， 然后生成 QA 解读页面。

7 📖 阅读所有材料
打开 audit/audit_report.html 查看自动扫描结果。 通读 LaTeX 源码（重点：摘要、引言、方法、实验）。 浏览代码仓库结构和关键实现文件。
🎯 所有文件都已下载好。你从一开始就能看到论文声明了什么、代码里有什么。
8 🔬 四维度深度审计
逐一检查每个维度，把发现直接写入 audit/audit_report.html （HTML 里有预留的占位区域等你去填）：
▼ 四大审计维度 ▼
🔁
可复现性
数据集有下载脚本吗？预训练权重提供没？ 对比的 baseline 是真的实现了，还是从别的论文抄了个数字？
🧩
方法一致性
逐行对比：论文说的 vs. 代码做的。 抓夸大其词——"新颖的注意力机制"其实只是标准多头 attention。
🔬
实验细节
超参数、数据预处理、评估指标——论文的描述和配置文件、 训练脚本里的实际设置是不是一回事？
📊
代码覆盖率
论文里的每个实验、每张表、每幅图——代码里有没有对应实现？ 标记出无法复现的结果。
9 💬 生成 QA 解读页面
默认执行：把论文引言翻译成三栏对照 HTML 页面 （qa/introduction.html）——英文原文 · 人话解释 · 中文翻译。
📝 每个自然段是一张卡片，读者可以像读带注释的双语指南一样浏览论文。 后续问题在 qa/ 目录下新建页面——同样卡片风格，一个问题一个 HTML 文件。
qa/introduction.html · qa/method.html · qa/experiments.html · …
✓ 审计完成
现在用户手里有一份完整的 audit/audit_report.html（四个维度都已填好）， 加上引言解读和后续问答页面。全部是自包含的 HTML 文件——浏览器直接打开，不需要服务器。
