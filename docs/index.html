📋 code-audit-paper

🔍 Audit Flow

code-audit-paper — from a paper title to a full audit report

1 📥 Parse the Input
You give the tool a paper reference — it can be an arXiv ID (like 2301.12345), a full paper title, or a complete arXiv URL. The tool automatically figures out which paper you mean and creates a clean, readable folder name for it (for example, the method acronym like "ResNet" or the first six words of the title).
💬 This is the entry point: just tell the tool which paper to audit, and it handles the rest. No need to manually download anything or create folders.
/code-audit-paper <paper title or arXiv ID or URL>
2 📄 Download the Paper from arXiv
The tool reaches out to arXiv.org through its official API. It always tries to get two things:
① The PDF — the typeset paper as you'd read it online. Almost always available.
② The LaTeX source bundle — the raw .tex files the authors wrote. This is the key part: without the LaTeX source, we can't do a deep audit (the PDF alone doesn't tell us what the authors really wrote before typesetting it).
📁 Everything lands in a folder like <paper_name>/paper.pdf and <paper_name>/latex/.
python3 scripts/fetch_arxiv.py "<query>" --output-dir <base_dir>
✅ LaTeX source found
📄 Source saved
The LaTeX bundle was downloaded and extracted into the latex/ folder. This gives us access to every .tex and .bib file — we can now read the paper's exact source, find GitHub links in the references, and inspect every claim the authors made.
❌ No LaTeX source
⛔ Cannot proceed
arXiv only has the PDF — no .tex files available. Without the raw LaTeX source, we can't automatically scan for code repository links or parse the paper's claims. The PDF alone is not enough for a reliable audit.
💡 The PDF is still saved. You can read it manually, but an automated deep audit is not possible at this point.
3 🔗 Find & Clone the Code Repository
This is the detective work. The tool reads every LaTeX file (and bibliography .bib files) to find GitHub links. It looks inside \url{}, \href{}{}, and nearby text to identify which link points to the actual code repository for this paper.
🔎 The tool is smart enough to skip links to datasets, dependency libraries, personal homepages, or unrelated repositories — it focuses on the paper's own implementation code. If no link is found in the LaTeX, it falls back to searching GitHub by paper title and shows you the top matches to pick from.
📦 Once the right repo is identified, the tool clones it into <paper_name>/code/. It then inspects the cloned repo to make sure it actually contains code (not just a README or empty project).
python3 scripts/fetch_code.py "<query>" --output-dir <base> --latex-dir <latex>
✅ Repository found
📦 Code cloned
The codebase has been downloaded into code/. All source files, configs, and scripts are now available for the audit.
✅ Has real code
▶ Continue
The repo contains Python source files, model definitions, training scripts, or config files — it's a genuine paper implementation.
❌ Empty / docs-only
⛔ Stop
The repo is just a README, a placeholder, or documentation with no actual implementation code. There is nothing to audit.
❌ No repo found
⛔ Stop
No GitHub link was found in the LaTeX, and the GitHub search didn't return a matching repository. At this point you can manually provide a repository URL, or conclude that the paper's code is not publicly available.
4 🧪 Run the Audit Engine
Now the real work begins. The audit script reads the LaTeX source to extract every claim the paper makes, then compares each claim against the actual code. It produces a detailed report covering four dimensions:
python3 scripts/audit.py <latex_dir> <code_dir> --output-dir <audit>
▼ Four Audit Dimensions ▼
🔁
Reproducibility
Are the datasets available? Are pretrained weights provided or linked? Are the baseline methods actually implemented, or just numbers copied from another paper? This answers: "Can I run this experiment myself?"
🧩
Method Consistency
Line-by-line comparison: what the paper says the model does vs. what the code actually does. Catches exaggerations like "novel multi-head attention" that turns out to be a standard 8-head attention.
🔬
Experiment Details
Checks if the training hyperparameters (learning rate, batch size, optimizer), data preprocessing, and evaluation metrics from the paper match what's in the code's config files and scripts.
📊
Code Coverage
For every experiment, table, and figure in the paper: is there corresponding code to reproduce it? Flags experiments that are described in the paper but have no implementation at all.
5 💬 Generate Human-Readable Q&A Pages
After the audit, the tool automatically translates the paper's Introduction into a three-column HTML page that you can open in any browser:
Left column (🔤) — the original English text, paragraph by paragraph.
Middle column (💡) — a "plain language" version that explains each paragraph in simple terms. Technical jargon gets parenthetical explanations, and complex ideas are broken down with analogies. Aimed at someone with basic AI knowledge (like an undergraduate CS student), not an expert in this specific subfield.
Right column (🀄) — an accurate Chinese translation.
📝 Each paragraph becomes a card on the page. You can scroll through and read the paper like an annotated, bilingual guide. If you have follow-up questions about the paper (like "explain the method" or "what does Table 3 show?"), you can ask, and additional Q&A pages will be created in the qa/ folder — each question gets its own HTML page in the same card-based style.
qa/introduction.html  ·  qa/method.html  ·  qa/experiments.html  ·  …

🔍 审计流程

code-audit-paper — 从一篇论文标题到一份完整审计报告

1 📥 解析你的输入
你给工具一个论文引用——可以是 arXiv ID（比如 2301.12345）、 论文完整标题，或者 arXiv 完整链接。 工具会自动识别你要审的是哪篇论文，并给它起一个干净易读的文件夹名 （比如用方法缩写 "ResNet"，或者取标题前六个词）。
💬 这就是入口：你只要告诉工具要审计哪篇论文，剩下的全部自动完成。 不需要手动下载任何东西，也不需要手动建文件夹。
/code-audit-paper <论文标题 或 arXiv ID 或 URL>
2 📄 从 arXiv 下载论文资料
工具通过 arXiv 官方 API 下载论文，每次都会尝试获取两种文件：
① PDF 文件——也就是你在 arXiv 网页上看到的那种排版好的论文。几乎总是能下载到。
② LaTeX 源码包——作者提交的原始 .tex 文件。 这是关键：没有 LaTeX 源码就做不了深度审计（光看 PDF 根本不知道作者真正写了什么、 有没有在排版时隐藏细节）。
📁 所有文件都会放到 <论文名>/paper.pdf 和 <论文名>/latex/ 目录下。
python3 scripts/fetch_arxiv.py "<查询>" --output-dir <输出目录>
✅ 有 LaTeX 源码
📄 源码已保存
LaTeX 源码包已下载并解压到 latex/ 文件夹。现在我们可以查看 每一份 .tex 和 .bib 文件——阅读论文的真正源文本、 在参考文献中搜索 GitHub 链接、逐一检查作者的每一项声明。
❌ 没有 LaTeX 源码
⛔ 无法继续
arXiv 上只有 PDF，没有 .tex 源文件。没有原始 LaTeX 源码， 就无法自动扫描代码仓库链接，也无法精确解析论文中的声明。 单靠 PDF 远远不足以做可靠审计。
💡 PDF 仍然会保存下来。你可以手动阅读，但自动深度审计到此为止。
3 🔗 查找并克隆代码仓库
这是侦探工作。工具会逐篇阅读所有 LaTeX 文件（包括参考文献 .bib 文件），从中找出 GitHub 链接。 它会检查 \url{}、\href{}{} 以及链接周围的文字， 判断哪个链接指向的是论文真正的代码仓库。
🔎 工具很聪明，会自动跳过数据集仓库、依赖库链接、作者个人主页等无关链接—— 只关注论文自己的实现代码。如果 LaTeX 里找不到任何 GitHub 链接，会自动转到 GitHub 上按论文标题搜索，把匹配度最高的几个仓库列出来让你选。
📦 确定目标仓库后，工具会把它克隆到 <论文名>/code/ 目录下，然后检查克隆下来的内容——确认里面确实有代码（不只是 README 或空项目）。
python3 scripts/fetch_code.py "<查询>" --output-dir <目录> --latex-dir <latex>
✅ 找到了仓库
📦 代码已克隆
代码库已下载到 code/ 目录。所有源文件、配置文件、 训练脚本现在都可以审计。
✅ 有实际代码
▶ 继续审计
仓库包含 Python 源文件、模型定义、训练脚本或配置文件——这是一个真正的 论文复现代码库，可以继续审计。
❌ 空壳 / 只有文档
⛔ 无法继续
仓库里只有 README、占位文件或纯文档，没有实际实现代码。没有代码可审计。
❌ 没找到仓库
⛔ 无法继续
LaTeX 里没有 GitHub 链接，GitHub 搜索也找不到匹配的仓库。 这时你可以手动提供一个仓库 URL，或者确认这篇论文的代码没有公开。
4 🧪 执行审计引擎
真正的审计从这里开始。审计脚本会通读 LaTeX 源码，提取论文中的所有声明， 然后把每一条声明和实际代码做对比。最终生成一份详细报告， 覆盖四个维度：
python3 scripts/audit.py <latex目录> <代码目录> --output-dir <审计输出>
▼ 四大审计维度 ▼
🔁
可复现性
数据集找得到吗？预训练权重提供了没？对比的 baseline 方法是真的实现了， 还是只从别的论文里抄了个数字？这一项回答："我能自己跑出论文里的结果吗？"
🧩
方法一致性
逐行对比：论文说模型做了什么 vs. 代码真正做了什么。 专门抓那些夸大其词的写法，比如"新颖的多头注意力机制"其实只是一个标准的 8 头 attention，没有任何特别之处。
🔬
实验细节
检查训练超参数（学习率、batch size、优化器）、数据预处理方式、 评估指标计算——论文里写的和代码配置文件里实际设置的是不是同一回事。
📊
代码覆盖率
论文里的每个实验、每张表格、每幅图：代码里有没有对应的实现脚本？ 标记出那些论文里描述了但在代码里完全找不到的实验——这些结果你无法复现。
5 💬 生成通俗易懂的 QA 解读页
审计完成后，工具会自动翻译论文的引言（Introduction）， 生成一个三栏对照的 HTML 页面，用浏览器直接打开就能看：
左栏（🔤）——英文原文，按自然段逐段展示。
中栏（💡）——"用人话说一遍"。用通俗易懂的语言解释每段在说什么， 遇到专业术语会加括号注释，遇到复杂概念会用类比帮助理解。 目标读者是普通人工智能专业本科生，不需要是本领域的专家。
右栏（🀄）——准确的中文直译。
📝 论文的每个自然段都是一张卡片（card），从上到下排列。 你可以像读一本带注释的双语指南一样浏览整篇论文。 如果你对论文有后续问题（比如"这个方法到底是怎么做的？""表 3 说明了什么？"）， 可以继续提问，工具会在 qa/ 目录下新建对应的 HTML 页面—— 每个问题一个独立网页，沿用同样的卡片风格。
