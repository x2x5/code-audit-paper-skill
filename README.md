# code-audit-paper

**用代码当证据，看看论文到底有没有吹牛。**

你读到一篇 AI 论文，说自己的方法"达到了 SOTA""提出了新颖的架构"——但代码里真的是这样吗？这个工具帮你自动下载论文和代码，然后逐条对比论文的声明和代码的实际实现，生成一份能在浏览器里看的完整审计报告。

🌐 **流程图和说明 → https://x2x5.github.io/code-audit-paper**

---

## 它做了什么？

两个阶段，从论文标题开始到一份完整审计报告结束：

| 阶段 | 做什么 | 产出 |
|------|--------|------|
| 📦 **阶段一：准备** | 环境检查 → 下载论文 PDF + LaTeX → 从源码确定目录名 → 克隆代码仓库 | 所有材料就绪 |
| 🔬 **阶段二：审计** | 自动扫描 → 四维度审计 → 生成 QA 页面 → 保存交接提示词 | `audit_report.html` + QA 页面 + `handoff_prompt.md` |

阶段二末尾还有一个**可选的深度重审**：如果你觉得首轮不够深，拿着 `handoff_prompt.md` 再跑一轮，产出一份更详细的 `audit_report_deep.html`（不修改原报告）。深度重审聚焦 4 个核心任务——全部围绕"代码和论文能不能对上"。

## 安装

```bash
git clone git@github.com:x2x5/code-audit-paper.git ~/.agents/skills/code-audit-paper
```

只需要 **Python 3.6+ 标准库**（不需要额外装任何包）外加系统里有 `git`。

## 怎么用

### 启动审计

```
/code-audit-paper <arXiv ID 或论文标题或 arXiv 链接>
```

比如：

```
/code-audit-paper 2301.12345
/code-audit-paper Attention Is All You Need
/code-audit-paper https://arxiv.org/abs/2301.12345
```

### 它会自动完成

1. **检查环境**——找到正确的 `python` / `git` / `pip` 命令
2. **下载论文**——从 arXiv 抓 PDF 和 LaTeX 源码
3. **确定目录名**——读完 LaTeX 源码后，用方法缩写（如 ResNet）或标题前 6 词命名
4. **找代码仓库**——扫 LaTeX 里的 GitHub 链接并克隆
5. **自动扫描**——生成 `audit_report.html` 脚手架
6. **四维度审计**——可复现性 / 方法一致性 / 实验细节 / 代码覆盖率
7. **生成 QA 页面**——引言三栏解读（英文 · 人话 · 中文）
8. **保存交接提示词**——写入 `handoff_prompt.md`

### 查看结果

用浏览器打开 `audit_report.html`——一份完整的审计报告就在你面前。

### （可选）深度重审

如果你觉得首轮不够深，打开 `handoff_prompt.md`，复制内容，开新窗口粘贴——它会做更深度的分析，输出一份独立的 `audit_report_deep.html`。你可以自己选用什么模型。

## 审计报告的四个维度

| # | 维度 | 通俗解释 |
|---|------|----------|
| 🔁 | **可复现性** | 数据集有下载方式吗？预训练权重给了吗？baseline 是真的实现了还是抄的数字？ |
| 🧩 | **方法一致性** | 论文说模型做了什么 vs. 代码里实际写了什么。抓夸大其词。 |
| 🔬 | **实验细节** | 学习率、batch size、数据增强——论文写的和代码配置的是不是一回事？ |
| 📊 | **代码覆盖率** | 论文里每个实验、每张表、每幅图——代码里有没有对应实现？ |

## 输出文件

```
audit_output/
  0722/                                  # 月日（审计日期）
    1914-visual-autoregressive-modeling/ # 时分-论文名
      ├── paper.pdf
      ├── paper.json
      ├── latex/                         # LaTeX 源码
      ├── code/                          # 克隆的代码仓库
      ├── audit/
      │   ├── audit_report.html          # ⭐ 首轮审计报告
      │   └── audit_report_deep.html     # （可选）深度重审报告
      ├── handoff_prompt.md              # 交接提示词
      └── qa/
          ├── introduction.html          # 引言三栏解读
          └── ...
```

目录名由三部分组成：**月日 / 时分 - 论文名**。论文名从 LaTeX 源码中提取（方法缩写如 ResNet，或标题前 6 词）。这样多个审计按时间自动排序。

所有 HTML 都是自包含的——浏览器直接打开，不需要服务器。

## 常见问题

**Q: 论文没有 LaTeX 源码（arXiv 只有 PDF）怎么办？**
报告中会如实标注。审计深度会受影响，但 PDF 审阅仍然可用。

**Q: 论文没有公开代码怎么办？**
报告中如实标注"代码不可用"。审计只能基于论文文本。

**Q: 目录名是怎么定的？**
不是提前猜的——下载完 LaTeX 源码后，从 `.tex` 文件中找方法缩写（如 ResNet、ViT）。找不到就用标题前 6 个单词。前面加上时间戳（月日/时分-），方便多次审计自动排序。

**Q: 深度重审和首轮审计有什么区别？**
首轮产出 `audit_report.html`，深度重审产出 `audit_report_deep.html`（更详细，含代码片段引用和行号，不修改原报告）。两者可以对比着看。

**Q: 需要对 arXiv 或 GitHub 做任何认证吗？**
不需要。arXiv API 公开，GitHub 公开仓库不需要登录。

## 设计原则

- **零外部依赖**：只用 Python 3.6+ 标准库 + git
- **脚本辅助，人做判断**：自动脚本负责提取和匹配，审计结论由模型阅读论文和代码后做出
- **输出即网页**：所有报告都是自包含 HTML，浏览器打开就能看
- **目录名后定**：下载完 LaTeX 源码后再确定目录名，用方法缩写而非 arXiv ID，加上时间戳前缀自动排序
- **首轮和深度分开**：深度重审不覆盖首轮报告，两份并存可对比
- **中文优先**：报告和解读面向中文用户
- **诚实记录**：没有代码就说没有，没有 LaTeX 就说没有
